# העלאת EAR לגוגל פליי — מה עושים ומה עלי

הקוד, החתימה והבנייה מוכנים. נשארו צעדים שדורשים חשבון וזהות שלך. אלה לא ניתנים לעשייה בשבילך.

## מה כבר מוכן בקוד
- בניית **App Bundle חתום** (`.aab`): workflow בשם **Android AAB (Google Play)**.
- **מחיקת חשבון בתוך האפליקציה** (לשונית "אני" ← "מחיקת החשבון שלי"). גוגל דורשת את זה.
- מזהה האפליקציה: `app.ear.mobile`. **אחרי שמעלים לפליי אי אפשר לשנות אותו**, אז החלט עכשיו אם הוא מתאים.
- הרשאות: אינטרנט בלבד, ותמונות רק כשבוחרים תמונת פרופיל.

## מה עליך לעשות (לפי הסדר)

### 1. חשבון מפתח בגוגל פליי
- נכנסים ל-https://play.google.com/console ונרשמים כמפתח. זה **תשלום חד־פעמי** (נכון לידיעתי 25$, כדאי לאמת באתר).
- ייתכן שיבקשו אימות זהות. חשבונות אישיים חדשים צריכים לעבור **בדיקה סגורה**: לפי הכללים הנוכחיים בערך 12 בודקים שמותקנים את האפליקציה כמה שבועות לפני שאפשר לפרסם לכולם. את הפרטים כדאי לאמת בקונסול.

### 2. מפתח חתימה (פעם אחת)
יוצרים קובץ מפתח ושומרים אותו **במקום בטוח** (אם הוא נאבד, אי אפשר לעדכן את האפליקציה בלי תהליך שחזור מול גוגל). לא מעלים אותו לריפו ולא שולחים אותו בצ'אט.

בטרמינל של GitHub Codespaces (או כל מחשב עם Java):
```
keytool -genkeypair -v -storetype JKS -keystore upload.jks -alias ear-upload -keyalg RSA -keysize 2048 -validity 10000
base64 -w0 upload.jks
```
הפקודה הראשונה שואלת סיסמאות ופרטים. הפקודה השנייה מדפיסה טקסט ארוך, וזה ערך הסוד הראשון.

ב-GitHub: **Settings ← Secrets and variables ← Actions ← New repository secret**. יוצרים ארבעה סודות:

| שם | ערך |
|---|---|
| `KEYSTORE_BASE64` | הטקסט הארוך מ-`base64` |
| `KEYSTORE_PASSWORD` | סיסמת הקובץ |
| `KEY_ALIAS` | `ear-upload` |
| `KEY_PASSWORD` | סיסמת המפתח |

### 3. בניית ה-AAB
**Actions ← Android AAB (Google Play) ← Run workflow.** בסיום מורידים את `EAR-aab` מה-Artifacts. אם חסר סוד, הריצה נכשלת מיד עם הודעה ברורה. בכל העלאה חדשה `versionCode` חייב לגדול (ברירת המחדל היא מספר הריצה).

### 4. יצירת האפליקציה בקונסול והעלאה
- Create app ← שם "EAR", שפת ברירת מחדל, אפליקציה, חינמית.
- Release ← Testing ← Internal testing (לבדיקה מהירה) ← מעלים את ה-`.aab`.
- מאשרים **Play App Signing** כשהקונסול מציע.

### 5. טפסי חובה בקונסול (App content)
- **Privacy policy:** כתובת העמוד `https://ear-8ii9.onrender.com/privacy`.
- **Account deletion:** מצהירים שיש מחיקה בתוך האפליקציה. כתובת העמוד: `https://ear-8ii9.onrender.com/delete-account`.
- **Data safety:** התשובות המוצעות מופיעות למטה.
- **Content rating:** שאלון. האפליקציה כוללת תוכן גולשים אנונימי, לכן מצהירים על **תוכן משתמשים (UGC)** ועל קיום דיווח וחסימה.
- **Target audience:** מבוגרים/נוער מגיל 13 ומעלה, לא ילדים. נשמח לאמת מול המדיניות הנוכחית.
- **Ads:** אין פרסומות.

### 6. חומרים לדף החנות
- אייקון 512x512 (יש בקוד: `apps/mobile/assets/icon.png`, צריך לוודא את הגודל).
- **תמונת Feature** 1024x500 וצילומי מסך מטלפון אמיתי (לפחות 2). את צילומי המסך אפשר לקחת ממכשיר אחרי ההתקנה.

## תשובות מוצעות ל-Data safety
מבוסס על מה שהמערכת באמת אוספת. כדאי לעבור על כל שורה ולאמת לפני שליחה.

| נתון | נאסף | מטרה | הערות |
|---|---|---|---|
| כתובת מייל | כן | ניהול חשבון | נדרש להרשמה |
| שם משתמש / שם תצוגה | כן | פונקציונליות האפליקציה | גלוי בפרופיל הציבורי |
| תמונת פרופיל | כן (אופציונלי) | פונקציונליות | |
| הודעות | כן | פונקציונליות | הודעות אנונימיות שנשלחות לחשבון |
| מזהי מכשיר ו־IP | כן, כערך גיבוב בלבד | מניעת ספאם והתעללות | נשמר 30 יום, לא כמזהה גלוי |
| טוקן התראות | כן | התראות | |

- **הצפנה במעבר:** כן (HTTPS).
- **בקשת מחיקה:** כן, בתוך האפליקציה ובעמוד המחיקה.
- **שיתוף עם צד שלישי:** לא נמכר ולא משותף למטרות פרסום. שליחת התראות עוברת דרך שירות ההתראות של Expo/Google (לאמת בהצהרה).

## בדיקה אחרונה לפני שליחה
1. מתקינים את ה-APK מהריליס ובודקים: הרשמה, שליחת הודעה מהאתר, קבלתה, מחיקת חשבון.
2. מעלים לבדיקה פנימית ומתקינים מהקישור של גוגל.
3. רק אחר כך עוברים לפרסום.
